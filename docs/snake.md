# Snake で測る「状況から動きを決める」力

`/v1/systemone` は選択肢ごとの確率を返す。分類に使うのが本来だが、**上下左右の4択**として使えば、そのまま
ゲームの操作になる。一手ごとに盤面を渡して「次はどちらへ？」と聞き、返ってきた確率の最大値へ動かす。
文章は生成しないので、一手＝プロンプト1回の評価で済む。

同じ盤面を **AA（文字）** と **画像** で渡して比べられるようにした。分類ベンチ（[jev.md](https://github.com/kishida/llama.cpp/blob/jev/docs/jev.md)
の比較表）が「1問に答える力」を測るのに対し、こちらは「盤面全体の制約を同時に扱う力」を測る。この2つが
別物であることが、はっきり出た。

比べるときの基準は **座標を添えない条件**にする。頭とりんごの座標を渡すと、モデルは盤面を走査せず
引き算で方向を出せてしまい、盤面の書き方を比べる実験が成立しない。座標アリは「盤面全体を見なくて済む
ヒントを与えたらどうなるか」という別の問いとして扱う。

## 決まりごと

- 10×10。蛇は長さ3、中央から右向きで開始。りんごを食べると1伸びる。
- 壁か自分の体に当たれば終わり。200手、またはりんごを60手食べられなければ打ち切り。
- 逆走の指示は、普通の Snake と同じく無視して直進する（死因にしない）。
- 1条件あたり10ゲーム、シードは 0〜9 で固定。どの条件も同じ盤面の並びを解く。

参考値として、サーバーを使わない方策も同じ枠組みで回す。

| 方策 | 平均スコア | 最高 | 平均手数 | 安全手 | 近づく |
|---|---|---|---|---|---|
| greedy（りんごに近づく安全な手） | 18.45 | 27 | 144.2 | 99.5% | 94.2% |
| random（でたらめ） | 0.10 | 1 | 13.7 | 68.5% | 41.8% |

**安全手** = 死なない方向を選べた手の割合（危険な方向がある局面だけを数える）。
**近づく** = りんごとのマンハッタン距離が縮む方向を選べた手の割合。この2つを分けて見ると、負け方が分かる。

## 盤面の渡し方

### AA（座標あり）

```
############
#..........#
#....oo....#
#A...ooo...#
#....o.....#
#....H.....#
#..........#
############

Legend: H = the snake's head, o = its body, A = the apple, # = the wall, . = empty.
The snake is 7 cells long and is currently moving down.
Moving up decreases the row, moving down increases it; left decreases the column, right increases it.
The head is at column 5, row 5. The apple is at column 1, row 3.
The snake dies if it hits the wall or its own body.
```

### AA（座標なし）

上の下2行（行・列との対応と、頭とりんごの座標）を外し、代わりに
`Up is towards the top of the board, down towards the bottom, left and right as shown.` を置く。
**画像版とまったく同じ情報量**になる。

### 画像

384×384 の PNG（12×12 マス × 32 px）。黒枠が壁、濃い緑が頭、薄い緑が胴、赤い丸がりんご。
**文字も座標も矢印も描かない**。色と位置と形だけ。添えるテキストは AA（座標なし）と同じ内容で、
記号の説明が色の説明に変わるだけ。

### 質問

```json
{"move": {"type": "choice",
          "instructions": "The snake must eat the apple without hitting a wall or its own body. Which direction should the snake move next?",
          "criteria": {"up": "move one cell up, towards the top wall", "down": "...", "left": "...", "right": "..."}}}
```

## 結果

### 基準は「座標なし」

盤面をどう渡すかを比べるので、**座標を添えない形を基準にする**。これは画像版とまったく同じ情報量で、
モデルは実際にグリッドを読まないと答えられない。座標を添えた条件は別立てで後に置く。

| モデル | 条件 | 平均 | 最高 | 平均手数 | 安全手 | 近づく | 1手 |
|---|---|---|---|---|---|---|---|
| Gemma 4 31B | 連続 | 2.9 | 6 | 33.3 | 95.8% | 82.3% | 715 ms |
| | スペース区切り | **4.2** | 6 | 39.2 | 95.4% | 90.1% | 1000 ms |
| | 画像 | **4.2** | 8 | 36.0 | 95.8% | 93.3% | 1987 ms |
| Qwen3.8 Flash-Next | 連続 | 1.6 | 4 | 31.5 | 96.5% | 72.1% | 384 ms |
| | スペース区切り | 2.2 | 8 | 21.9 | 91.3% | 82.2% | 616 ms |
| | 画像 | **6.1** | 12 | 53.0 | 96.8% | 92.8% | 815 ms |
| Qwen3.6 27B | 連続 | 1.2 | 3 | 16.9 | 93.5% | 78.7% | 680 ms |
| | スペース区切り | 0.5 | 2 | 19.8 | 94.4% | 67.2% | 1009 ms |
| | 画像 | **3.4** | 8 | 31.8 | 93.7% | 88.4% | 1277 ms |
| Qwen3.6 35B A3B | 連続 | 0.0 | 0 | 6.1 | 26.2% | 55.7% | 144 ms |
| | スペース区切り | 0.0 | 0 | 7.0 | 20.0% | 58.6% | 318 ms |
| | 画像 | **3.7** | 9 | 34.4 | 91.9% | 93.6% | 329 ms |
| Qwen3.8 27B | 連続 | 0.0 | 0 | 8.9 | 65.2% | 73.0% | 704 ms |
| | スペース区切り | 0.0 | 0 | 7.0 | 42.9% | 81.4% | 1170 ms |
| | 画像 | **0.9** | 2 | 25.6 | 96.1% | 55.1% | 1325 ms |
| GLM-5.3-Flash | 連続 | 0.0 | 0 | 6.4 | 84.4% | 35.9% | 3125 ms |
| | スペース区切り | 0.2 | 1 | 5.9 | 79.7% | 42.4% | 4421 ms |
| | 画像 | 0.1 | 1 | 7.0 | 85.7% | 40.0% | 6350 ms |

**同じ情報量なら画像が強い**。6モデル中5モデルで画像が最高で、残る Gemma 4 31B も画像とスペース区切りが
同点。35B-A3B は文字だと 0.0（安全手 26%）なのに画像なら 3.7（安全手 92%）と、別のモデルのように変わる。

**文字で渡すならマス目を区切ったほうがいい**。Gemma 4 31B が 2.9 → 4.2、Flash-Next が 1.6 → 2.2。
連続した `#.....H....#` は隣り合う文字が1トークンにまとまってしまい、列がずれる。区切ればマスと
トークンが対応する。Qwen3.6 27B だけ逆に落ちる（1.2 → 0.5）が、10ゲームでは揺れの範囲。

### ヒントを足すと上がる — ただし盤面を読まなくなる

座標を添えると、モデルは盤面全体を走査しなくてよくなる。

```
The head is at column 5, row 5. The apple is at column 1, row 3.
```

| モデル | 座標なし | 座標あり | 差 |
|---|---|---|---|
| Qwen3.8 27B | 0.0 | **4.7** | +4.7 |
| Qwen3.8 Flash-Next | 1.6 | **6.0** | +4.4 |
| Qwen3.6 27B | 1.2 | 4.4 | +3.2 |
| Gemma 4 31B | 2.9 | 5.5 | +2.6 |
| Qwen3.6 35B A3B | 0.0 | 1.4 | +1.4 |
| GLM-5.3-Flash | 0.0 | 1.1 | +1.1 |

効果は大きい。**Qwen3.8 27B は 0.0 から 4.7 になる** — 座標がなければ一度もりんごに届かないモデルが、
座標を足すだけで上位に並ぶ。内訳を見ると「近づく」が 73.0% → 97.0% とほぼ満点になる一方、「安全手」は
65.2% → 90.3% と、りんごへの方向ほどには上がらない。**引き算でりんごの向きは出せるが、壁と自分の体は
引き算では出てこない**からだ。

裏を返せば、座標アリのスコアは盤面の読解をほとんど測っていない。**盤面の書き方を比べるなら座標は外す**。

座標アリでスペース区切りにすると、逆に成績が落ちる（Flash-Next 6.0 → 4.7、Qwen3.8 27B 4.7 → 3.2）。
盤面のトークンが倍になり、その後ろに置かれた座標の行が遠ざかって埋もれるためで、グリッドの読みやすさとは
別の現象。座標なしでは同じことをしても上がるので、区切り自体が悪いわけではない。

### 規模：9B と 27B の間に段差がある

以下は座標アリで測った古い一連の実験で、**条件が上とは違う**（座標アリなので盤面の読解は測れていない）。
モデル間の相対比較としてだけ読む。Qwen3.5 系列と、分類ベンチの正解率を並べる。

| サイズ | 分類 正解率 | Snake 平均 | 最高 | 平均手数 | 安全手 | 近づく |
|---|---|---|---|---|---|---|
| 27B | 0.914 | **3.00** | 12 | 25.2 | 86.5% | 98.0% |
| 9B | 0.885 | 0.10 | 1 | 6.0 | **33.3%** | 91.7% |
| 4B | 0.852 | 0.00 | 0 | 6.6 | 50.0% | 78.8% |
| 2B | 0.709 | 0.00 | 0 | 5.3 | 62.3% | 28.3% |

分類は 0.709 → 0.914 となだらかに伸びるのに、Snake は 9B まで実質ゼロで、27B だけ別物になる。
**分類 0.885 の 9B が Snake で手も足も出ない**のがこの実験のいちばんの収穫だった。

9B の内訳を見ると理由が分かる。「近づく」は 91.7% と高いのに「安全手」が 33.3%（ランダム以下）しかない。
**りんごは見えているが、壁と自分の体が見えていない**。2つの制約を同時に満たすところで落ちている。

Gemma 4 12B も同じ壊れ方をする（近づく 98.8%、安全手 57.0%、平均 0.80）。しかも confidence 0.834 と
自信たっぷりに間違える。

### 世代：ほぼ差がない

同じ 27B・同じ量子化（UD-IQ3_XXS）。

| モデル | AA（座標あり） | AA（座標なし） | 画像 |
|---|---|---|---|
| Qwen3.5 27B | 3.00 | 0.00 | 2.60 |
| Qwen3.6 27B | 4.20 | 1.40 | 2.30 |
| Qwen3.8 27B | 3.60 | 0.00 | 2.20 |

10ゲームの平均なので、この程度の差は揺れ。分類ベンチでも 0.914 / 0.919 / 0.914 と横並びだった。
ただし座標なし AA だけは 3.6 が 1.40 で他の2つが 0.00 と、開き方が大きい。

### MoE：総パラメータではなく活性パラメータで効く

座標アリ。ただしこの結論は座標なしでも変わらず、むしろ強くなる（35B-A3B は座標なしの文字で 0.0、
安全手 26.2%）。一方で画像なら 3.7 まで戻るので、足りないのは盤面を*文字から*読む力のほうらしい。

| モデル | 分類 正解率 | 分類 1問 | Snake AA | 安全手 | 近づく |
|---|---|---|---|---|---|
| Qwen3.6 27B（密） | 0.919 | 355 ms | **4.20** | 91.5% | 98.2% |
| Qwen3.6 35B-A3B（活性 3B） | 0.913 | **187 ms** | **0.80** | 64.9% | 93.5% |

分類では密な 27B と同じ精度を半分の時間で出すのに、Snake では 27B の5分の1。9B と同じ壊れ方
（近づく 93.5% に対し安全手 64.9%）をする。**選択肢から1つ選ぶには活性 3B で足りるが、盤面全体を
同時に扱うには足りない**。LFM2.5 8B-A1B（活性 1B）が分類 0.587 に留まったのと同じ話が、
分類で差が出ないモデルでも起きる。

### 分類向けの学習は効かない

座標アリ。

| モデル | 分類 正解率 | Snake AA | 安全手 | 近づく |
|---|---|---|---|---|
| jwenv 1.7B poc（Jev 用に学習） | 0.804 | 0.20 | 75.0% | 33.3% |

分類では 8B 級に迫るが、Snake はランダム同然。当然ではあるが、**分類の学習は空間推論を与えない**。

### りんごの形

画像で、りんごを四角から丸に変えた（Qwen3.8 27B）。

| りんご | 平均 | 最高 | 平均手数 | 安全手 | 近づく | 死因 |
|---|---|---|---|---|---|---|
| ■ 四角 | 1.80 | 7 | 62.9 | 97.8% | 59.5% | 足踏み7 / 壁3 |
| ● 丸 | 2.20 | 6 | 62.2 | 98.2% | 64.5% | 足踏み3 / 壁4 / 自分3 |

平均の差は10ゲームでは小さいが、**死因が変わる**。四角のときは「60手りんごに着けず足踏み」が7回だったのが
3回に減った。胴体と同じ四角だと色だけで見分けることになるが、丸にすれば形で分かる、ということらしい。

### 速度

一手あたり。画像は AA の 2〜3倍かかる（毎回エンコードし直すため）。

| モデル | AA | 画像 |
|---|---|---|
| Qwen3.5 2B | 61 ms | 206 ms |
| Qwen3.5 9B | 192 ms | 401 ms |
| Qwen3.6 27B | 673 ms | 1168 ms |
| Qwen3.6 35B-A3B | 254 ms | 575 ms |

## 分かったこと

- **盤面を読めているモデルはごく少ない**。座標を外すと、Qwen3.8 27B・Qwen3.6 35B-A3B・Qwen3 32B は
  文字の盤面で 0.0、つまり一度もりんごに届かない。残るのは Gemma 4 31B（2.9）と Flash-Next（1.6）だけ。
- **同じ情報量なら画像のほうが強い**。6モデル中5モデルで画像が最高。35B-A3B は文字 0.0 / 画像 3.7 と
  極端で、モデルが盤面を読めないのか、*文字の*盤面を読めないのかは分けて考える必要がある。
- **ヒントは効くが、測っているものを変えてしまう**。頭とりんごの座標を足すと Qwen3.8 27B は 0.0 → 4.7。
  盤面全体を走査せずに引き算で方向が出せるようになるからで、そのスコアは盤面の読解を測っていない。
- **文字で渡すならマスを区切る**。座標なしなら Gemma 4 31B 2.9 → 4.2、Flash-Next 1.6 → 2.2。ただし
  座標アリでは逆に落ちる。盤面のトークンが倍になって座標の行が埋もれるためで、別の現象が混ざる。
- **分類の成績は、この種の課題の成績を予測しない**。0.914〜0.923 に収まる5モデルが、座標アリの Snake で
  0.5 から 4.7 まで散らばる。分類のために学習した jwenv 1.7B もランダム同然だった。
- **負け方を2つに分けて見ると診断できる**。「近づく」が高く「安全手」が低ければ、目標は見えていて障害物が
  見えていない。両方低ければ盤面を読めていない。Gemma 4 31B だけは死因の9割が自分の体で、
  壁は越えたその先で負けている。
- それでも greedy（18.45）には遠い。座標なしの最高（Flash-Next の画像 6.1）でも3分の1に届かない。

## 動かし方

```bash
# 対局と記録（サーバーは llama-server の /v1/systemone）
python demo/snake/play.py --mode text --minimal --games 10 --url http://127.0.0.1:18160 --tag min_foo
python demo/snake/play.py --mode board --board space --minimal --games 10 --tag spacedmin_foo
python demo/snake/play.py --mode image --games 10 --tag image_foo    # 要 --mmproj
python demo/snake/play.py --mode text --games 10 --tag text_foo      # 座標アリ（参考）
python demo/snake/play.py --mode greedy --games 20                   # 参考値、サーバー不要

# モデルを順に立てて一括で
python demo/snake/run_all.py
```

記録は `results/snake/<tag>.json`（全フレームの盤面・確率・選んだ手つき）。

**見る**:

```bash
python -m http.server 8777           # このリポジトリの直下で
```

- 再生: http://127.0.0.1:8777/demo/snake/replay.html
  実行とゲームを選んで再生。コマ送り、スライダー、←→キー。右側にそのコマの4方向の確率が出て、
  選んだ手は濃色、進めば死ぬ方向には × が付く。一覧は `results/snake/index.json` で決まる。
- ライブ: `python demo/snake/live.py --url http://127.0.0.1:18160 --mode text` → http://127.0.0.1:8800/
  裏でゲームを回し続け、一手ごとに SSE で流す。死んだら次を始めるので置きっぱなしにできる。
  累計のゲーム数・平均・最高と直近のログも出る。モデルサーバーが落ちても止まらない。
